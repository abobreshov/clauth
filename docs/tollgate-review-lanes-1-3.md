## Notes

1. **C4, the `mcpOAuth` merge.** The finding also proposed merging the quarantined slot's `mcpOAuth` into `mcp-logins.json`. That was not done. `mcp-logins.json` is only parked and restored for a profile that stores no credentials file (`claude::park_mcp_logins`), and a session-token profile stores one, so the merged block would never be read. The quarantined copy keeps the bytes, and a rollback restores them.
2. **The duplicate-carrier rule.** Quarantine is inert: tollgate never reads `quarantine/` as a login, and `tollgate delete` removes it with the profile. The superseded store under `--adopt-live` holds a different chain, and a session-token profile's live copy holds a refresh token found nowhere else. In neither case does a chain live in two carriers tollgate refreshes.
