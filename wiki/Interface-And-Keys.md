# Interface and keys

`tollgate` opens on the Overview tab (or the `home_tab` you set). <kbd>←</kbd> <kbd>→</kbd> or <kbd>tab</kbd> / <kbd>⇧tab</kbd> move between tabs at the top level, and <kbd>⌥1</kbd>–<kbd>⌥9</kbd> jump straight to a tab. While a detail pane has focus the arrows are trapped: <kbd>←</kbd> returns to its selector and <kbd>→</kbd> does nothing there. <kbd>tab</kbd> / <kbd>⇧tab</kbd> still switch tabs from a descended read-only detail (Usage, Tokens model, or Status) and do nothing in a descended editable pane. <kbd>?</kbd> lists every binding for the tab you are on, <kbd>q</kbd> twice quits.

The header's first row reads `tollgate vX.Y.Z`, then a `[ guest ]` pill while upstream clauth owns `~/.claude` ([Guest mode](Guest-Mode)), then a dim `[ herdr ]` tag inside a herdr pane, and the `[ daemon ]` chip on the right. In guest mode every switch and capture answers with a toast naming guest mode instead of acting; the plugin install, the `mcpServers` wiring and the herdr config fix write only tollgate's own entries ([Guest mode](Guest-Mode#tollgates-own-entries)).

Colours follow the `palette` key: the running Omarchy theme when there is one, else Catppuccin Mocha, reloaded live when the theme changes ([Configuration](Configuration#palette)). There is no Config tab row for it.

Page Up and Page Down move the focused list, detail, form or modal by its viewport less one row, keeping an overlap. Lists and forms stop at their ends and keep each newly selected row visible; modal buttons stay pinned while their body scrolls. The terminal needs at least 34 columns and 14 rows.

## Tabs

| Tab | Holds | You can |
|-----|-------|---------|
| **Overview** | account table, live 5h / long-window bars (7d, or Alibaba's monthly quota), chain position, selectable codex accounts | switch Claude accounts, select Codex accounts, reorder Claude accounts, open an account in Setup |
| **Usage** | per-account window breakdown for every Claude Code and codex account: 5h, 7d, per-model weeks, extra-usage spend, peak-rate state, a codex account's own facts and windows; below the profiles, every monitor and (in guest mode) every upstream clauth account, as metric cards | scroll detail, edit a Claude Code account's note, refresh one Claude Code account, toggle estimates and the pace marker |
| **Tokens** | global Claude Code token stats and API-equivalent cost | focus and scroll dashboard cards, drill into models, change the period lens, count cache tokens |
| **Setup** | the Overview's account list (Claude Code, codex and Hermes rows), then each Claude Code account's endpoint, key, env, model routing, auto-start, usage probe, 5h alert | edit any of it, log in, log out, disable or delete a Claude Code account, create a claude or codex account, re-login or delete a codex account |
| **Fallback** | the auto-switch chain | reorder members, edit thresholds, flip gates, set a spend ceiling |
| **Config** | program-wide settings | change any of the rows in the table below |
| **Status** | incidents from status.claude.com with per-component health | open an incident's timeline or its page in a browser |
| **Plugin** | Claude Code wiring health, per-profile runtime state, running delegates | apply one-key fixes |

An Overview row showing `same account as <name>` has resolved to the same Anthropic account as that profile. Login warns about the likely browser-account mix-up in a toast. The Fallback tab names the duplicate blocker, and walks skip later duplicates until their login resolves to another account.

The active account is orange. Its mark sits in the marker column, in orange: `✻` on a claude account, cycling `· ✢ * ✶ ✻ ✽` and back (Ghostty draws its own set) while that account is spending tokens, and `⏣` on a codex account. A red `!` marks an account whose 5h alert fired until usage falls below the line; it outranks the active mark. A `▲` on an account's row means the provider behind it is on peak-rate hours right now — some providers charge more at set times of day (DeepSeek roughly doubles its API rate; Z.ai's GLM peak hours consume the coding plan's quota faster). The active account's mark outranks `▲` on its own row, so an active account on peak hours keeps its mark and `▲` shows on the other accounts. The Usage tab's `pricing` row names the state, the countdown to the next switch, and nothing renders for flat-rate accounts. The marker follows the provider's own published rate schedule, never which models the profile pins; an account on an endpoint tollgate doesn't recognize shows none. A codex account's banked usage-limit resets show as `↺ N` on its Overview row while one is available — `tollgate limit-reset` spends one ([Codex](Codex#use-a-usage-limit-reset)). Usage numbers are cached on disk, so they stay on screen when the API is rate-limited or unreachable. Once those figures age past the refresh cadence's stale threshold, the Usage tab's status block adds a `[ stale ]` pill; it reads the age of the reading — an OAuth account's own fetch stamp, one it cannot date reading stale at once, or a third-party account's cache write time — not the last fetch outcome, so a `[ cached ]` pill and it can appear together. An amber `⋯` in place of the refresh countdown marks a cached reading tollgate no longer polls. A red `⊘` before an account's name marks a long-lived setup token that is expired, mis-filled, or refused by the server to the usage probe; a refused one is a dead login no automatic switch lands on, and its figures stay as they are until a new token is captured with `tollgate login <name> --setup-token`, a probe reads it again, or the probe is switched off, which clears them. On the fallback chain panel below the accounts, `↲ ~40m` beside a member names the account the chain switches to next, and roughly when. When the panel is too short to show every member, its last line reads `+N more · → fallback tab`: N members are off-screen, and the Fallback tab, four tabs to the right (<kbd>→</kbd> or <kbd>tab</kbd>), lists them all.

**Monitors and upstream accounts on the Usage tab.** The Usage tab's account rail lists the profiles first, then each `monitor:<id>` from `monitors.toml`, then, in guest mode, each `upstream:<name>` read from upstream clauth's status feed. <kbd>↑</kbd> <kbd>↓</kbd> walk the whole rail and wrap. Selecting one of those extra rows shows it as metric cards: a header with the provider and plan, a stale or failure line when there is one, then one card per window (label, reset countdown with local time, a full-width bar with an elapsed marker `│`, the value with a pace glyph `↑ → ↓` and a severity word, a dim footnote) and one per money meter (balance, a folded spend row, caps and budgets). They are read-only and have no Setup tab row; `tollgate monitor refresh` fetches a monitor. The list is re-read from disk every 2 seconds, so a monitor added from the shell appears without a restart.

An account's `t/s` column sits after `live`: its live speed, blank where the producer carries none, dropped whole first on a narrow terminal, before the 7d reset stamp sheds a cell, and given up to the wall-clock reset stamps when `reset_display` is `clock` or `both` and both do not fit. The Usage detail lists `speed` and `rate` rows under its header: the `speed` row reads `live · 5m · 1h · today · peak` and the `rate` row `live · 5m · 1h · today` (speed = output ÷ generation time, rate = output ÷ window length): a rate reads `0` under a fresh producer when the account spent nothing, a speed reads `—` when no response touches its window, and every figure reads `—` while no fresh producer stands behind the cache. The Tokens tab's today card carries a `speed` row (`S t/s now · S t/s today · S tok/s peak`), the TOTAL card an `avg speed S t/s · S t/s peak · S tok/s peak` row once a day of speed history exists (what each peak means: [Tokens and cost](Tokens-And-Cost#token-speed)), and the trend chart a speed strip under its bars with `· avg S t/s` on its caption — the strip drops before the month ticks on a short card.

Codex accounts ([Codex](Codex)) sit under the Claude Code rows in a section headed `codex`, in the same columns: name (bold, in the blue accent, when it is the active codex profile, with `⏣` in the marker cell), plan, 5h and 7d, with `—` where nothing is cached, and a dim `↺ N` after the columns while the account holds a banked usage-limit reset ([Codex](Codex#use-a-usage-limit-reset)). <kbd>↑</kbd> and <kbd>↓</kbd> reach every codex account. Switch a Codex account with `tollgate <name>`; <kbd>⏎</kbd> does nothing on a Codex row, <kbd>s</kbd> has no Codex binding, and <kbd>a</kbd> opens tab-wide actions without an account group. Account-specific Claude actions and reordering stay on Claude rows. Codex rows have no live, t/s or timer cell. A codex row shows the same `×` marker when its chain is quarantined, and its plan cell falls back to the plan the account's login claims while no poll has cached one. Hermes profiles ([Hermes](Hermes)) follow in a section headed `hermes`: name, `provider · mode`, a green `●` while a session holds the home, and this month's spend in the 5h column (`$4.12 mo`, `—` with no reading). They are read-only too, since a Hermes home switches by relaunch, and a Hermes profile never appears among the monitors; <kbd>⏎</kbd> or <kbd>s</kbd> on one says `'<name>' is a Hermes profile; Hermes switches by relaunch: 'tollgate start <name>'` and switches nothing. The accounts panel is titled `ACCOUNTS`, and its right edge shows the by-harness counts (`52 claude · 1 codex · 2 hermes`, an empty roster's harness omitted), the first thing to go on a narrow terminal. The header's line 2 opens with `[ N live ]  [ R tok/s ]`, then holds the gauge with its speed suffix and the status dot: `N live` is every live session tollgate can see, whatever account it runs on, split as `[ 6+7 live ]`: the end user's own sessions first, then `tollgate mcp` delegates in the blue accent, with a dim `+` between the parts (a zero part drops with its `+`, so delegates alone read `[ 7 live ]` in blue; both zero read dim `[ 0 live ]`, and `[ — live ]` when tollgate cannot read where it tracks them); `R tok/s` is the fleet's live token-consumption rate off the speed cache, dim at `0` and at `—`, the latter while no fresh producer stands behind the cache; the gauge carries the active account's live speed as `(S t/s)` (dim, absent when the gauge is or when the account has no fresh live speed). A narrow terminal drops the tok/s chip first, then the live chip, then the speed suffix, then the gauge's own ladder, then the status dot.

The Usage tab lists the same accounts as Setup, without `+ new`, then the monitor and upstream cards described below. A codex account's detail shows `type  codex`, its plan, `login  [ needs re-login ]` while its chain is quarantined, `resets  ↺ N banked` while it holds a banked reset, how long ago its usage was read, then whichever of its 5h and 7d bars it reports.

## Keys

### Everywhere

| Key | Action |
|-----|--------|
| <kbd>←</kbd> <kbd>→</kbd> (or <kbd>tab</kbd> / <kbd>⇧tab</kbd>) | previous / next tab at the top level; in a descended detail <kbd>←</kbd> returns to the selector and <kbd>→</kbd> does nothing, while <kbd>tab</kbd> / <kbd>⇧tab</kbd> still switch tabs from a read-only detail and do nothing in an editable one |
| <kbd>⌥1</kbd>–<kbd>⌥9</kbd> | jump straight to a tab (<kbd>⌥9</kbd> is always the last); live inside an editor and a descended pane |
| <kbd>↑</kbd> <kbd>↓</kbd> | move the selection, or scroll a detail pane |
| <kbd>⏎</kbd> | act on the selected row (see below) |
| <kbd>n</kbd> | new account (on the Overview, the form's `type` is preset from the row under the cursor; a suspended form comes back as you left it) · on a Claude Code row of the Usage tab: edit the account's note |
| <kbd>d</kbd> | open the divergence resolver, when one is pending |
| <kbd>x</kbd> | dismiss the oldest toast, then the footer alert; over an open dialog it dismisses the oldest toast only; while a field is open for editing, <kbd>x</kbd> stays with it. Any <kbd>x</kbd> also cancels a pending quit and clears its alert (never the `saving …` line) |
| <kbd>a</kbd> | action menu for the current row |
| <kbd>?</kbd> | keybinding help for this tab |
| <kbd>esc</kbd> | step back out of a sub-pane; in an open text field, put back the saved value (the footer reads `esc revert`), or on the new-account form keep what you typed (`esc done`) |
| <kbd>q</kbd> | step back, or arm quit at the top level; press again to confirm (over changed work the second press opens the loss warning) |
| <kbd>ctrl</kbd>+<kbd>c</kbd> | arm quit from anywhere; press again to confirm (over changed work the second press opens the loss warning) |

A descended Usage or Tokens model detail scrolls one line with <kbd>↑</kbd> / <kbd>↓</kbd>; <kbd>esc</kbd> or <kbd>←</kbd> returns to its selector without changing the selected account or model. <kbd>pgup</kbd> / <kbd>pgdn</kbd> move one page, the visible height less one line: a list or form moves its selection about a page and stops at the first or last row, and no line is passed over unseen. An open text field whose value runs past its row scrolls sideways with the caret, keeping the character you are on whole in view, and the usage tab's note editor does the same with a line wider than it. Choice dialogs and action menus follow the selected option so it remains visible; an overflowing choice shows a scrollbar. A custom-field overwrite whose consequence cannot fit in the choice dialog opens a confirmation with its full explanation scrollable (<kbd>↑</kbd> / <kbd>↓</kbd> and the page keys, while <kbd>←</kbd> / <kbd>→</kbd> pick the button) and cancel selected by default; a fitting choice acts at once. Toasts stack in the top-right corner, at most three lines each: a longer message ends its third line in `…`, and a failure leads with what went wrong and why.

A switch away from an open edit whose typed value differs from the one it opened from — a Setup account field, the `+ new` form, a Fallback or Config field, the Plugin tab's herdr tag field, or the Usage note editor — opens a `WARNING` dialog instead of switching: `go back · discard · save`, with `save` selected. `save` checks every changed value first and, if they all pass, commits each and performs the switch (or quit); if any is refused, none is committed, the dialog closes, and the failing item's own `↵` runs — a rename or env key toasts its reason. A quit while an account is saving a refreshed login (a claude or codex token rotation, a rolling token's re-stamp, or an account switch) or while an account delete runs waits, the footer naming that account, and exits once that write ends, however it lands; a usage read never holds a quit, though a refresh that must first rotate the account's token waits for that rotation. During the wait the footer reads `saving … · ⌃c ⌃c quit now`; a second quit exits at once, after at most 2 s more for a running token spend. A changed value whose `↵` would open a further dialog (an env-key collision) stops the save the same way and opens that dialog. `save` over a mix that includes the `+ new` form commits the saveable rest, then reopens the two-button `discard them and switch?` dialog. `discard` drops the work as `esc` would and performs the switch (or quit); `go back` (or `esc`) closes the dialog and keeps the edit, text and caret intact. The `+ new` form has nothing to save, so it warns with `go back · discard`, `go back` selected. A quit — a second <kbd>q</kbd> at the top level or a second <kbd>ctrl</kbd>+<kbd>c</kbd> from anywhere — over changed work opens the same dialog in its quit form (`save them before quitting?`), and a second <kbd>ctrl</kbd>+<kbd>c</kbd> over a switch's warning turns it to the quit form; over a quit's warning it does nothing more. An unchanged open edit suspends silently and re-seeds from a newer saved value on return, caret at the end.

On the Tokens dashboard, <kbd>↑</kbd> / <kbd>↓</kbd> move focus card to card in reading order (wrapping), <kbd>PageUp</kbd> / <kbd>PageDown</kbd> move about a page and stop at the ends, and the grid scrolls by whole cards when it is taller than the screen: a card that does not fit whole moves below the fold, with a scrollbar in the body's right edge, instead of clipping its border.

### Tab-dependent

|-----|----------|
| <kbd>r</kbd> | Usage: refresh the selected Claude Code account only; nothing on a codex row, which refreshes on the refresh interval alone. Tokens / Status / Plugin: reload that tab's data. Everywhere else: refresh every Claude Code account. In the tollgate process that fetches usage, a refresh of an account the usage probe reads sends it a probe, which is billed and may start that account's 5h window, so refreshing every account there sends one to each such account |
| <kbd>t</kbd> | Tokens: cycle the period lens. Everywhere else: force-rotate every Claude Code account's token, after a confirm |
| <kbd>⏎</kbd> | Overview: switch to the selected Claude account; Codex rows are selection only. Usage: descend into the selected account's detail to scroll its full breakdown. Tokens: open the model breakdown, then descend into the selected model's detail; a view with no model has no detail to open. Setup / Fallback: open a detail row, or commit an edit; on a Fallback card's `preferred days` row, open the day picker. Status / Plugin: open the detail |
| <kbd>⇧↑</kbd> <kbd>⇧↓</kbd> | Overview: reorder Claude accounts. Fallback (chain focus): reorder chain members |
| <kbd>space</kbd> | Config: cycle a value. Setup: cycle the `model` row and the `+ new` form's `type`, flip `auto-start` and `usage probe`, open the `alert at` and `probe every` editors. Fallback toggle rows: flip. Fallback `preferred days`: step `never` → `weekdays` → `weekends` → `every day` and back to `never`, saving each step; a custom set is one more stop after `every day` until you leave the card |
| <kbd>+</kbd> <kbd>-</kbd> | Fallback detail: step `rotate at` or `weekly at` by 5; Setup: step `alert at` by 5 and `probe every` by 30s |
| <kbd>e</kbd> | Overview: open the selected account in Setup's editor: on its `+ login` / `re-login` row when its login is broken (`×`) or it holds none, on its `api key` row when its key is rejected (`key rejected` on its Fallback card), else on its first row, where a refused setup token (`token rejected` on its Fallback card) opens too, since no row mints a new one (`tollgate login <name> --setup-token` does); a codex row opens its own Setup pane on its first row. Usage local profiles: toggle burn estimates |
| <kbd>p</kbd> | Usage local profiles: toggle the ideal-pace marker |
| <kbd>c</kbd> | Tokens: count cache reads and writes in the token totals |
| <kbd>f</kbd> | Plugin: apply the selected row's fix |
| <kbd>m</kbd> | Overview: move a live `tollgate start` session onto the selected account (below) |

**Moving a live session (<kbd>m</kbd>).** On an Overview account row, <kbd>m</kbd> lists the running Claude Code sessions as `sid · now on · executor · state`. "Now on" is the account the session's requests authenticate as. <kbd>↑</kbd> <kbd>↓</kbd> pick one, <kbd>⏎</kbd> moves it, and <kbd>esc</kbd> closes the list. The move is the one `tollgate switch <sid> <profile>` makes ([Auto-switch](Auto-Switch#moving-a-live-session-by-hand)), and a toast reports the result: `session <sid>: swapping… onto <p>` for an API-key hot swap, `session <sid> stays on <cur>: <reason>` when the target is not hot-swappable, and `session <sid>: relaunch with 'tollgate switch <sid> <p> --relaunch'` for a session only a relaunch can move. The TUI never relaunches a session. It works in guest mode, since it writes only the session's own registry row.

The Overview's `live` cell counts `tollgate start` sessions on each account. It ends in `⇄` when one of them follows the fallback chain, and in `…` while one of them is mid hot swap: committed to another account, with its key helper not yet serving the new key. Until the helper serves it, the session is counted on the account whose key it still sends.

The day picker on a Fallback card's `preferred days` row shows each weekday as `[x]` or `[ ]`: <kbd>←</kbd> <kbd>→</kbd> walk the days (and do not switch tabs while it is open), <kbd>space</kbd> toggles the day and saves at once, <kbd>⏎</kbd>, <kbd>esc</kbd> or <kbd>q</kbd> leave it, and <kbd>↑</kbd> <kbd>↓</kbd> leave it and move to the row above or below. <kbd>?</kbd> and <kbd>x</kbd> keep working while it is open; every other key does nothing until you leave, except <kbd>⌥1</kbd>–<kbd>⌥9</kbd>, which still jump to a tab and suspend the picker.

On macOS, <kbd>t</kbd> skips any account holding a live `tollgate start` session or an unfinished background job holding the rotating login: that session's login lives in a Keychain item tollgate cannot write, so rotating it would sign the session out. An account a background `--with-fallback` session has moved off is not skipped, since the session no longer reads that login.

On macOS, tollgate checks the `Claude Code-credentials` Keychain item at startup and before any change that replaces it: a switch, `log out`, deleting or renaming the active account, creating a new account, a login or capture, clearing a long-lived token, or a choice in the divergence resolver. When a bare `claude` left a login there that no account has saved and tollgate cannot tell whose it is, it shows a `KEYCHAIN LOGIN` dialog with three rows: `s  save`, `p  replace` and `c  cancel`. <kbd>↑</kbd> <kbd>↓</kbd> pick a row and <kbd>⏎</kbd> chooses it, <kbd>s</kbd>/<kbd>p</kbd>/<kbd>c</kbd> answer directly, and <kbd>esc</kbd> or <kbd>q</kbd> cancels. `save` with two accounts that could own the login opens a `SAVE LOGIN` picker asking `save it into which profile?`; `save` with no account matching asks for a new name. While a check runs, including the one after a `save`, a pick or `replace`, the toast `checking the macOS Keychain login…` shows until it answers; a switch shows its usual spinner on the account's row instead. At startup the dialog's rows offer to relink the active account rather than switch. If a check, a `save` into an existing account, a pick or `replace` stops unexpectedly, the change it held does not run and a toast says so: `<change> failed`, then `tollgate hit an internal error, restart tollgate`.

On Usage, <kbd>⏎</kbd> enters the selected account's detail, including monitor cards. On Tokens, it opens the model list, then enters the selected model's detail. In either detail pane <kbd>↑</kbd>/<kbd>↓</kbd> scroll one row and <kbd>page up</kbd>/<kbd>page down</kbd> scroll a viewport; <kbd>←</kbd>, <kbd>esc</kbd> or <kbd>q</kbd> returns to the selector. <kbd>tab</kbd>/<kbd>⇧tab</kbd> still changes tabs. Long lists and settings forms keep the selection and wrapped hints visible across moves and resizes.

On Usage, <kbd>n</kbd> edits the selected local profile's note. <kbd>⏎</kbd> saves, <kbd>ctrl</kbd>+<kbd>j</kbd> inserts a newline, and <kbd>esc</kbd> cancels. Characters produced with Alt/Option are text when Control is not held. Clearing the draft deletes the note. An unreadable note or invalid UTF-8 opens no editor and shows an error, preserving the original file for repair by hand. Notes live in each profile's private `note.txt` under `~/.tollgate` with mode 0600; they are absent from status and agent API output. Monitor-only cards have no note editor or estimates/pace toggles. On an empty roster <kbd>n</kbd> still creates an account.

The header shows the fleet's live session total as a counter chip, including bare sessions, without shifting its gauge when the first session starts. Ordinary toasts last five seconds; warning/error toasts retain their longer lifetime. Each toast carries a severity word, wraps by terminal cell width and shows at most three rows, ending in `…` when clipped. Keys and commands named in prose use the theme's accent. Displayed percentages use at most two decimals, with trailing zeros removed.

## Action menus

<kbd>a</kbd> opens the actions available for whatever is selected. It lists what no key already does, so on Config, Fallback and Plugin, where every action already has a key, it holds only the daemon entry every tab ends on. The footer only advertises <kbd>a</kbd> where something would open.

Entries above the rule act on the account named in the menu's title bar; entries below it act on the tab, and the last one on the daemon.

| Tab | Account | Tab-wide |
|-----|---------|----------|
| Overview | `refresh usage`, `rotate access token`, `disable account` / `enable account`, `open provider console` | `refresh all accounts`, `new account` |
| Usage | `refresh usage`, `rotate access token`, `disable account` / `enable account`, `open provider console` (none on a codex row) | `refresh all accounts`, `toggle estimates`, `toggle pace marker` |
| Tokens | none | `period: lifetime` / `daily` / `weekly` / `monthly`, `show all models` / `show claude models` / `show other models`, `toggle cache counting`, `reload stats` |
| Setup | `duplicate account`, `save as preset`, `apply preset`, `verify login` (`v`), `open provider console` (none on a codex row) | none |
| Status | none | `refresh status`, `open in browser` |
| every tab | none | `start daemon` / `stop daemon`, last |

`start daemon` shows while no daemon runs and starts `tollgate daemon` in the background, detached from the TUI: it keeps running after you quit the TUI or close its terminal, and writes its log to `~/.tollgate/daemon.log`. It starts the plain daemon, so it serves no REST API; for a remote client, run `tollgate daemon --listen` yourself ([Daemon](Daemon)). `stop daemon` shows while one runs and stops it the way `tollgate daemon --replace` does, taking the shunt gateway down with it (a daemon that takes over at once, such as a standby, runs its own). Neither shows while one of them is still working; a toast reports how it went.

The active period or model filter is omitted from the Tokens menu, so the entries you see are the ones that would change something. `open provider console` follows the same idea from the other direction: it appears only on an account whose endpoint tollgate knows a key page for, so an OAuth account's menu is one entry shorter.

The Setup detail pane is itself a list of actions, so <kbd>⏎</kbd> on a row is the action. What the menu adds is what works on the account as a whole, from either the account list or a settings row, and none of it on a codex row (its detail rows carry the actions). On the `+ new` form there is no account to duplicate or save, so its account entry is `apply preset` alone, offered only while `type` is `claude`, stamping the draft's endpoint and model fields.

| Entry | Does |
|-------|------|
| `duplicate account` | asks for a name, then copies every setting onto a new account: endpoint, api key, env, models, thresholds. The stored login stays behind, as do the chain's `preferred` and `last resort` marks, which only one account may hold |
| `save as preset` | stores this account's base url and models under a name you type ([Configuration](Configuration#presets)). An existing preset asks first; a built-in's name is refused |
| `apply preset` | opens the picker, built-ins first. Applying replaces the endpoint and the whole model block, naming the fields first when any are set. <kbd>d</kbd> deletes a saved preset |
| `verify login` (`v`) | reads the stored OAuth login's account once, without rotating the token; available with credentials and hidden while verification runs. Reports identity changes and duplicate accounts in a local toast |
| `open provider console` | opens the page this account's api key is minted on, in your browser. Only for DeepSeek, Z.ai, OpenRouter, MiniMax, Ollama Cloud (and the local Ollama daemon, whose usage key is minted on the same page) and Alibaba Model Studio endpoints, so it is absent on an OAuth account and on any endpoint tollgate does not recognise. An Alibaba account gets its own plan's page: Token Plan and Coding Plan are separate products, on separate pages, per console; a Qwen Cloud account gets Qwen Cloud's API Keys page |

Applying a preset writes the endpoint and model values it sets and keeps fields it leaves unset. If an unset field already has a value, the confirmation offers `keep them` by default or `clear them`. This also applies to the `+ new` draft.

There is no `remove field` because none is needed: an env row's <kbd>⏎</kbd> edits its value, and an empty value removes the key. Editing it back is the same row.

`disable account` from Overview or Usage asks first, since disabling drops the account from auto-switch, usage polling and status mid-flight; re-enabling is immediate. Neither runs for the active account or for one holding a live `tollgate start` session — a Claude Code background job naming one of the profile's runtime trees (launched with `tollgate start <p> -- --bg`) counts as a live session, a stopped one too, until `claude rm <id>` (in an `--isolated` session, an unfinished one only), and so does a handed-off `--with-fallback` background session ([Auto-Switch](Auto-Switch)) on every account it has run on; the pick names whichever is in the way.

## Setup tab rows

The saved account’s `alert at` row sets the 5h usage alert threshold. `+` and `-` step it by 5 from 95%; Enter accepts 0–100 and an empty value turns it off.

The list is the Overview's own: Claude Code rows, then a `codex` band, then a `hermes` band, and `+ new` last. Selecting a Claude Code row opens its settings (rows below); selecting a codex row opens that account's own detail pane, and a Hermes row a read-only one naming `tollgate start <name>`. `+ new` turns the pane into the create form, which opens on a `type` row cycling `claude` / `codex`; <kbd>n</kbd> presets the type from the row under the Overview cursor (a codex row → `codex`, any other → `claude`), and from any other tab it opens a claude form; a suspended form comes back as you left it, so the preset applies to a fresh form only. Cycling `type` keeps the name you typed and asks first before it drops a staged login.

The claude form offers `name`, `base url`, `api key` (only once a url is typed), `model`, `+ model override`, `+ login` (only while the base url is empty, minting the OAuth login) and `create account`; after `+ login` (or in its place on an api form), `+ capture current login` stashes the login Claude Code is using now (it appears only while that login exists and no saved account owns it). `create account` saves every field, and a captured login from a different endpoint than the form's takes none of the form's model rows. The codex form offers `name`, `+ login` (codex's own browser login, staged until `create account`), `+ capture current login` (only while your own codex CLI login exists and is uncaptured; it stages that login) and `create account`; `create account` with nothing staged refuses on its own `└` line, and `+ login` and `+ capture current login` refuse a name either roster already holds on the name row, while `create account` refuses a name held by then with a `create failed` toast.

A codex account's detail shows `type  codex`, its `plan`, a `login  [ needs re-login ]` pill only while the chain is quarantined, then `re-login` (codex's browser login, as `+ login`; the modal offers <kbd>r</kbd> open again and <kbd>c</kbd> copy link, no paste) and `delete account` (press twice).

Rolling: `rolling · re-stamps in ~Nh`, `rolling · re-stamp due` inside the last hour, `rolling · no recorded expiry`, and `rolling token stalled` once nothing re-stamped it in time. `mis-filled` is neither: the sidecar holds a rotating pair the split cannot use. `token rejected` comes before all of them once the server refused the setup token: the account is a dead login whatever the expiry says. ## Plugin tab

An installed `tollgate@tollgate` plugin older than this tollgate build shows a warning and offers install/update, including when it is disabled. The install confirmation states that it enables the plugin.

Each row is a check on your Claude Code wiring: `tollgate` on `PATH` and `claude --version`, the `mcpServers` entry and whether `tollgate mcp` boots, the plugin install record (with a `completions` line when `$SHELL` names bash, zsh or fish and its completion script is not current), and each profile's runtime state. While a live daemon is still running the old binary, or its binary was removed, a warning line saying which and naming `tollgate daemon --replace` closes the `plugin` detail; it moves no health. A `herdr` row joins them when [herdr](Herdr-Plugin) is installed. <kbd>f</kbd> applies a fix on rows that offer one, behind a confirm that defaults to cancel:

| Fix | When it appears |
|-----|-----------------|
| `wire mcpServers into ~/.claude.json` | the entry is missing, project-local only, or points somewhere stale. Writes the tollgate entry into `~/.claude.json` and the copy in every shared runtime tree under `~/.tollgate/profiles/` (isolated trees excluded), leaving a file that already carries it alone. It refuses with a `wire failed` toast carrying one of four lines: `tollgate is syncing Claude Code's config; try again in a moment`, `{path} is being written by Claude Code; try again in a moment`, `{path} does not parse as a JSON object; nothing was changed`, `failed to write {path}` |
| `repair credentials` | the active profile's stored login disagrees with the live one |
| `relink credentials` | the active profile's credential link is missing while its stored credentials are intact |
| `add the keybinding and sidebar row to herdr's config` | the herdr plugin is installed but its key is unbound or its sidebar row is untemplated |
| `install plugin` | the plugin row reads not installed, installed for this project only, or installed at a version older than this tollgate (its `version` line then names both, `0.4.4 (this tollgate is 0.5.0)`). Confirms into the real `claude plugin` installer at user scope, which updates an older install and turns the plugin on; refuses with a toast while this dashboard is still running the old binary or its binary was removed ([Claude Code plugin](Claude-Code-Plugin)). In guest mode it, like `wire mcpServers` and the herdr fix, writes only tollgate's own entries ([Guest mode](Guest-Mode#tollgates-own-entries)) |
| `update completions` | the completion script installed for the shell `$SHELL` names (bash, zsh or fish) differs from what this tollgate prints for `tollgate completions <shell>`; the plugin row warns. Rewrites it the way `tollgate completions install` does, adding a `source` line to `~/.bashrc` or `~/.zshrc` if it has none; refuses with a toast while this dashboard is still running the old binary or its binary was removed |
| `install completions` | the script at the path `tollgate completions install` writes (`~/.tollgate/completions/tollgate.<shell>`; fish `~/.config/fish/completions/tollgate.fish`) is missing for the shell `$SHELL` names (bash, zsh or fish); installs it the same way, and leaves the row's health alone |

Page Up and Page Down read the selected check’s diagnostic output, including the prose above the herdr options. The footer advertises these keys while the detail overflows. Arrow keys return to the herdr options.

The `herdr` row's detail takes focus: <kbd>⏎</kbd> on the row descends, <kbd>↑</kbd>/<kbd>↓</kbd> walk the options rows, <kbd>space</kbd> or <kbd>⏎</kbd> activates one (toggle, cycle, or open the tag-refresh editor), <kbd>+</kbd>/<kbd>-</kbd> step the refresh, <kbd>esc</kbd> closes the editor and then ascends. `delegate row text` opens a confirm that defaults to cancel.

The `delegates` pane underneath lists the plugin's running `delegate` jobs. It binds no key: a delegate is stopped through the plugin's `monitor` tool ([Claude Code plugin](Claude-Code-Plugin)).
